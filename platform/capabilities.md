# EIPS — CAPABILITY MAP

What the platform actually does today, not an aspirational list.

**Ownership (decided 2026-07-29)**: CyberDudeBivash is the accountable
owner — documentation, capability, release, operational, support, and
executive — for every capability in this table. This was the single
governance gap the GEPMP v1 audit found blocking every capability from
reaching "Certified" status; recorded here as a decision made, not a
default assumed. If ownership is ever split across multiple people/roles,
update the Owner column per-row at that point rather than leaving this
blanket statement stale.

**Rewritten in full (GPLCIP v1)** — the previous version predated four
full sprints of real work (report publication, backup/restore, auth
observability, pricing fixes, FAQ) and had gone stale despite this file's
own rule that it be updated in the same commit as any capability change.
That rule was not followed across those sprints; this rewrite is the
correction, not a claim that the rule will now be followed perfectly going
forward — treat "last touched" per row as the actual freshness signal.

**Lifecycle Status** uses GPLCIP v1's taxonomy: Active / Improving /
Stable / Monitor / Candidate for Refactoring / Candidate for Retirement.

## How to keep this current

This table decays the moment a new capability ships without an update.
Update it in the same commit that changes a capability's status,
dependencies, or ownership. If that discipline slips again, the honest
thing to do is what the GPLCIP v1 rewrite did: say so plainly and
re-verify, not silently patch one row and leave the rest stale.
