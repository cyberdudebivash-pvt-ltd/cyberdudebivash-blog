# Vercel Migration Inventory

Evidence-based inventory of everything Git-visible that controls this
project's Vercel deployment. Produced during P0-A forensic reconnaissance,
2026-08-16, on branch `transformation/vercel-recovery-production-hardening`
(base `03f8d3837`). Every claim below is anchored to a file path (and line
number where useful) in this repository as of that commit. Nothing here was
inferred from a Vercel dashboard, API, or CLI — this session has no Vercel
credentials or API access of any kind. Where the repo cannot answer a
question, that is stated as `NOT VERIFIED` rather than guessed.

Cross-referenced against `OPERATIONS.md` and `RUNBOOKS.md` (this repo's own
existing operational docs). Discrepancies between those docs and what's
actually implemented are called out explicitly below rather than silently
resolved in either direction.

---

## 1. Deployment model

Static HTML + Vercel serverless functions under `api/`. **No build step**:
`package.json` has no `build` script, no framework dependency (`next`,
`nuxt`, `vite`, etc. — none present), and `vercel.json` declares no
`buildCommand`/`installCommand`/`outputDirectory`/`framework`. Content
(`posts/`, `cve/`, `api/intel/**`) is generated by scripts and committed
directly to git; Vercel serves it as-is.

Deploys trigger on every push to `main` via Vercel's native GitHub
integration (confirmed: no workflow in `.github/workflows/` calls the
Vercel CLI or API — see §4). This matches `OPERATIONS.md:17`'s own
statement and was independently confirmed live: the smoke-test workflow
triggered by this session's own push to `main` at `982b106df` completed
successfully ~20 minutes prior to this document.

## 2. `vercel.json` (root, 172 lines)

Keys present: `version`, `ignoreCommand`, `functions`, `headers`,
`rewrites`, `redirects`, `cleanUrls`, `trailingSlash`. **Absent**: `regions`,
`crons`, `builds`, `buildCommand`, `installCommand`, `outputDirectory`,
`framework` (confirmed by direct grep — zero matches for any of these keys).

- **`ignoreCommand`** (line 3): `"bash vercel-ignore-build.sh"` — see §3.
- **`functions`** (lines 6–15): per-route memory/duration overrides for 8
  routes (`api/v1/intel.js`, `api/v1/auth.js`, `api/v1/billing.js`,
  `api/v1/admin.js`, `api/v1/billing/webhook.js`,
  `api/v1/billing/razorpay-webhook.js`, `api/cron/dispatch-intel.js`,
  `api/og.js`). No explicit `runtime` override — Vercel's Node default
  applies, consistent with `package.json`'s `engines.node: ">=18.0.0"`.
- **`headers`** (lines 17–114): 8 source-matched blocks — CORS+CSP
  (`default-src 'none'`) on `/api/v1/(.*)`, cache/type headers on
  `/api/cron/(.*)`, `/api/(.*).json`, `/rss.xml`, `/sitemap.xml`,
  `/robots.txt`; a full CSP on `/(.*).html` with an explicit `script-src`
  allowlist (`cdnjs.cloudflare.com`, `googletagmanager.com`,
  `google-analytics.com`, `checkout.razorpay.com`) and `connect-src`
  allowlist (own domain, GA endpoints, `api.rss2json.com`,
  `api.allorigins.win`, `corsproxy.io`, `thingproxy.freeboard.io`,
  Razorpay); a catch-all `/(.*)` for HSTS/`X-Frame-Options`/
  `Referrer-Policy` (lines 104–113).
- **`rewrites`** (lines 116–163, 27 entries): two groups — internal-path
  blocking (`/CLAUDE.md`, `/Sentinel-APEX/:path*`, `/eito/:path*`,
  `/platform/:path*`, `/prompts/:path*`, and 3 named `.md` files, each
  rewritten to `/api/_lib/blocked-404`), and pretty-URL → query-string
  mapping for the `api/v1/**` surface plus `/feed`, `/feed.xml`,
  `/atom.xml` → `/rss.xml`.
- **`redirects`** (lines 165–167): `/rss` → `/rss.xml` (permanent).
- Last modified: commit `f0fdd397` (2026-07-27).

**This is the sole source of redirect/rewrite/header configuration** — no
`_redirects` file, no `next.config.*`, no root-level `middleware.js` exists
(the only `middleware.js` in the repo is `api/_lib/middleware.js`, an
internal auth/rate-limit helper imported by handlers, not Vercel Edge
Middleware).

## 3. `.vercelignore` (root, 32 lines) and the build-skip mechanism

`.vercelignore` excludes from the **deployment bundle** (not from git):
`CLAUDE.md`, `Sentinel-APEX/`, `eito/`, `platform/`, `prompts/`, `scripts/`,
`docs/`, `marketing/`, `BUSINESS-TRANSFORMATION-ROADMAP-2026.md`,
`AUDIT-REPORT-2026-05-28.md`, `OPERATIONS.md`, `RUNBOOKS.md`, `backups/`.
Its header comment (lines 5–14) states this is the actual access-control
mechanism for those paths — not `robots.txt` — and records that
`CLAUDE.md` and `Sentinel-APEX/README.md` were previously live and
Google-indexed before this file was fixed (commit `71ea6e28f`,
2026-07-28). `scripts/publication-engine/` (added this session) is
excluded from deployment by this same rule, as intended — it is
CI/dev-time tooling, not runtime code.

`vercel-ignore-build.sh` (root, 36 lines) is the real skip logic: it reads
the last commit message and, if it matches a bot-commit pattern
(`"SENTINEL APEX"*`, `"syndication: auto-published"*`,
`"🛰 [SENTINEL APEX]"*`), builds only when `HOUR % 2 == 0 AND MIN < 10`;
any other (human) commit always builds. Its own header comment states the
reason: bot pushes were exhausting the Hobby plan's 100-deployments/day
quota. Last modified commit `60bfd8e67` (2026-07-31).

**Discrepancy vs. `OPERATIONS.md`**: `OPERATIONS.md:37–44` (self-dated
"Last verified: 2026-07-05") documents a *different* mechanism — a Vercel
dashboard "Ignored Build Step" keyed on a `[skip ci]` tag in the commit
message. That is not what `vercel-ignore-build.sh` actually checks. The
doc predates the script's last edit by over three weeks and is stale on
this point. **Recommendation**: update `OPERATIONS.md` §1.1 to describe
the actual implemented mechanism, or reconcile the two if the dashboard
setting `OPERATIONS.md` describes was in fact also configured separately
(`NOT VERIFIED` — dashboard state is invisible to this session).

## 6. The un-declared cron — a known gap, not a known unknown-unknown

`api/cron/dispatch-intel.js` (header comment, lines 1–16) is written
assuming Vercel Cron invokes it on a schedule, forwarding a
`workflow_dispatch` to GitHub Actions. **`vercel.json` has no `crons` key
at all.** If this cron is/was active, its schedule was configured directly
in the Vercel dashboard and **is not recoverable from git** — this must be
manually recreated, not restored. It requires two env vars documented
*nowhere* else in this repository (not in `.env.example`, not in
`OPERATIONS.md`/`RUNBOOKS.md`): `CRON_SECRET` and `GITHUB_DISPATCH_TOKEN`
(the latter described in-code as "a fine-grained GitHub PAT scoped to
Actions:write on this repo only" — see `ENVIRONMENT_VARIABLE_MATRIX.md`).

`NOT VERIFIED`: whether this cron was ever actually enabled in the lost
account, and on what schedule.
