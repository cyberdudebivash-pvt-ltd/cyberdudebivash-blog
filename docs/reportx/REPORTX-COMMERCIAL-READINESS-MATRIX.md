# ReportX Commercial Readiness Matrix

The literal 23-row matrix Section 33/46 requires, generated by
`sentinel_engine.reportx.commercial_readiness.evaluate_commercial_readiness()`
and printed by `python3 cli.py reportx-gate <bundle.json>`. Every row below
is real tool output, not hand-typed — reproduce it with:

```bash
cd Sentinel-APEX/engine
python3 -m pytest tests/reportx/test_commercial_readiness.py -v
```

or by loading `tests/reportx/test_commercial_readiness.py`'s
`_build_fully_supported_bundle()` directly and calling
`evaluate_commercial_readiness()` on it.

---

## How to read a row

Every row's status is computed from another module's real output — no
row in this file, or in the code that produces it, is a hand-set boolean.
Three possible values:

- **PASS** — the underlying gate ran and found no defect.
- **FAIL** — the underlying gate ran and found a real defect (contradiction,
  missing evidence, schema contamination, stale review, QA defect, etc.).
- **BLOCKED** — the input the row needs (forecasts, regulatory
  determinations, a depth assessment, ...) is simply absent from the
  bundle. Per Section 46's literal "23/23 PASS" mandate, **BLOCKED counts
  against the roll-up exactly like FAIL** — there is no "23-minus-BLOCKED"
  partial credit. A genuinely commercial-ready bundle has zero BLOCKED
  rows because every required input was actually supplied.

## Why BLOCKED counts against the roll-up

This is the one place in the whole system where "no data" is
deliberately treated as harshly as "wrong data." The alternative — letting
BLOCKED rows pass by default — would let a thin, rushed report claim
commercial-readiness just because nobody attempted a forecast or a
regulatory read. Section 46 rejected that explicitly ("If even one row
cannot truthfully PASS: NOT COMMERCIAL-READY"), and
`fortune_500_commercial_deliverable`'s implementation
(`commercial_readiness.py`, control 23) enforces it as
`all(r.status == "PASS" for r in results)` — not
`all(r.status != "FAIL" for r in results)`. That one-word difference is
the actual mechanism behind "no manual PASS field, no partial credit."
