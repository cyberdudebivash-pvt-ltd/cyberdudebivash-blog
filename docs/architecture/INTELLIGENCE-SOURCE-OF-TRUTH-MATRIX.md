# Intelligence Source-of-Truth Matrix

**Date:** 2026-08-24
**Purpose:** prevent a repeat of the campaign delivery integrity incident (a second, divergent state store silently drifting from the canonical one) by recording, per intelligence domain, exactly one canonical source and every derived consumer. Scoped to the live/automated intelligence-core domains this and the preceding Phase 0 audit round actually verified — not a claim of completeness across the entire platform (e.g. `docs/architecture/module-ownership.md`'s `lib/intelligence/*`/`lib/ioc/*` TypeScript layer is a separate system not re-audited here).

**Rule this document exists to enforce:** if you are about to add a second place that stores or derives data already covered by a row below, stop and either extend the canonical source or get an explicit, documented reason why not, before writing code — matching this repository's own `platform/open-issues.md` Issue 1 precedent (Python-vs-JS graph/scoring duplication), which is exactly the failure mode this table exists to prevent from recurring.

## Why Campaign has two contributing sources, not one

Unlike every other row, Campaign identity and core attributes live on the graph (`Campaign`-type nodes, accumulated via `addNode()`'s upsert, which was already correct before this round), while the *richer* per-campaign projection (full `related_intel[]` detail, `shared_iocs`, per-item flags) lives in the separate `campaigns.json` artifact built by `campaign-engine.js`. This is not accidental duplication in the Issue-1 sense (two independently-evolving implementations of the same capability) — the graph node is intentionally a lighter identity/attribute record, and `campaigns.json` is intentionally the richer, API-facing projection derived from it. The actual defect this round fixed was that the *derivation* direction had a one-way data-loss bug (the projection didn't accumulate the way its source did), not that two systems disagreed about what a campaign is. Verified post-fix: the two are now in exact ID-set agreement (`graph campaign IDs == campaigns.json campaign IDs`, checked directly against production data, both counts 1,187).

## Maintenance rule

Update this table in the same commit that changes which system owns a given intelligence type's canonical state, mirroring `platform/capabilities.md`'s own stated discipline (and its own admission that discipline has slipped before — see that file's "How to keep this current" section). A stale row here is exactly the kind of silent-drift risk this document exists to prevent.
